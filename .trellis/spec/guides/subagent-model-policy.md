### 1.2 仍然有效的铁律

1. **派发前必须问用户用哪个模型**，得到确认后才允许派发；禁止静默用主代理模型。
2. **模型名一律不视为全称**（用户写的、历史记的、文档里的都算近似名）：必须到**对应通道的
   实际可用清单**里取精确串，把候选 + 推荐呈给用户点选；禁止把近似名当正确名写进命令。
3. **禁止用 `Kimi K3` 做子代理**（用户 2026-09-21 起长期有效）。
4. 每次派发 prompt 首行必须是 `Active task: <task.py current 的任务路径>`。
5. 派发 prompt 必须自包含（范围 / 问题 / 期望产出 / 是否允许写代码）。
6. 子代理产出即弃；**跨阶段记忆由主代理维护**。用户要求的「互相检查」按**链式交叉**落实：
   A 产出 → B 审 → C 复核，而不是让多个子代理共享同一上下文。
7. 只读型研究子代理只允许写任务 `research/` 目录，**不得**修改产品代码。

### 1.4 「约 400k 上下文」的处理口径

子代理的上下文上限**不是可设开关**（由模型窗口决定，无参数可调）。落实用户意图的方式是：
**每个子代理只负责一件专项、通读大文件（不做片段抽样）、产出即弃**；
跨阶段记忆、去重与最终结论由主代理维护。
「互相检查」通过**第二轮交叉复核子代理**实现（审上一轮产物），不通过共享上下文实现。

## 二、编排自主权：收尾类动作不问，冲突才问

> **来源**：用户 2026-09-24 明令。原文：
> 「这些不用问，你编排，这个写入规则，除非有冲突」。

### 2.1 默认自主

主代理对以下**收尾类 / 低风险 / 可逆**动作**自行编排并直接执行**，
不得为逐条征询而打断用户：

- 补齐文档（README / README_EN / 任务笔记）与版本号同步；
- 回填任务 PRD / implement 的验收勾选与结论；
- 清理已归档任务的重复副本、已注销的 worktree 残留、临时产物；
- 归档、日志、spec 沉淀、四绿门禁重跑；
- 按已确认方案继续未完成的实现步骤。

判定口径：**做错了也只是返工、不会造成不可逆损失**的动作 → 自主执行。

### 2.2 例外：必须停下询问

出现以下任一情形，**必须立即停下并征询用户**，不得自行拍板：

| 情形 | 为何要问 |
|---|---|
| **冲突**：验收标准与实测数据不符、子任务结论互相矛盾、规则与规则打架 | 需要用户裁决取舍，主代理无权单方面放宽或修改验收标准 |
| **不可逆**：删除/覆盖已有文件、丢弃未提交改动、重写历史、清理分支 | 影响不可回收 |
| **环境变更**：安装依赖、改全局配置、动代理/网络设置 | 影响面超出本仓库 |
| **方向性取舍**：架构方案二选一、重构 vs 重写、技术选型 | 影响项目走向，须用户选定 |
| **超出范围**：发现的问题需要扩大改动面才能修 | 范围变更应由用户决定 |

### 2.3 组合执行

自主执行时，把同批可做的收尾项**一次性编排完并汇报结果**，
而不是每做完一件就回来问一次"下一件做什么"。汇报时给出：
做了什么、证据（命令/行号/实测数据）、遗留什么。

### 2.4 与其他规则的关系

- 本节**不豁免**安全规则：`CyberDomain PARDON` 治理铁律（全局规则 §6）
  仍然有效——「删除/覆盖文件」「安装包」等**不可逆**动作依旧必须显式确认。
- 本节与 2.1 的"清理残留"不冲突：清理**未被任何提交引用的临时残留**属自主范围；
  删除**已跟踪的正式文件**仍走询问。
