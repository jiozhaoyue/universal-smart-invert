## ③ 归因表（原因 / 证据 file:line / 本次对策）

### A. 验收标准是"机制自证式"的，不含观感判据（最高权重）

- **原因**：4 轮的 AC 全部落在三类里：①门禁命令全绿；②"某条 CSS/文本/字符串满足某正则"；③"清单项数相等"。
  这三类都**只能证明"实现做到了我以为要做的事"，不能证明"用户看到的东西对"**。v6-4 的 AC 把这条推到了极致：
  「token 逐字节一致」「零颜色字面量」「emoji 计数为 0」「大纲 91 项 ⟷ schema 逐键比对」——
  任意一条全绿，**界面上仍可能一个按钮都看不见**，因为"边框存在且可见"不是任何一条的谓词。
- **证据**：
  - `test.js:5032-5321`（v6.4 token / 控件库块）：断言的是**字节一致**（`test.js:5078`）、**零字面量**（`test.js:5095,5097`）、
    **零 emoji**（`test.js:5304`）、**单个工厂只有一处定义**（`test.js:5215` 附近）。无一条测观感。
  - v6-4 自己的自白：`implement.md:264-266`「据此修掉**三处断言与单测都看不见**的缺陷」；
  - `implement.md:5256`（test.js R2c 注释）「这一整类……直到**面板截图才被眼睛发现**」。
  - 第 4 次任务的 prd.md:84 已经点名此机制：「禁止出现『存在某条 CSS 规则』这类自证式验收 ——
    这正是前 4 次重建失效的机制」。
- **本次对策**：把每条投诉翻译成**对计算样式/几何/交互的数值断言**（见 §4 P1/P2/P3/P5）。
  AC3 已按此写（读每个按钮的 computed style，断言 `border-width>0` 或等价分离）—— 但**必须再加"可见性"门槛**
  （对比度或有效像素差），否则 `border: 1px solid transparent` 也能让 `border-width>0` 成立（popup 的 `.tab` 就是反例，`popup.html:40`）。

### B. AC 只查"漏项"，从不查"重复项"与"层级"（冗余得以存活的直接原因）

- **原因**：v6-4 的双向核对断言是 `schema 键 ⟷ 面板键` **双向 ⊆**（`test.js` R1b 块，implement.md:142-148），
  它保证"没有键被落下"，但**对同一个键在一处出现两次、或在两处各出现一次完全无感**。
  v4 的 "zero redundancy" 只是 Requirements 里的一句话，没有 AC、没有断言 → 无法守护。
- **证据**：
  - `hoverRestore` 双开关：`@13711` / `@14504`（同写 `state.hoverRestore`）。
  - `imageInvert` 四处：`@13369`（胶囊）/`@13751` 区块 / `@12544`（schema 自认"同一个开关"）。
  - options 与模态两份全量页：v6-4 prd.md:117（options 91 项）＋ prd.md:122（面板逐项一致）＝**AC 强制的复制**。
- **本次对策**：`research/04` 产出**冗余矩阵**；AC4 要写成「同一界面内**无重复键**」＋「两处同名项语义与默认值一致」，
  且**冗余矩阵里每一组重复必须有处置决定（合并 / 分层 / 删除），未处置即红**（见 §4 P6）。

### C. 三次重建都只重建"信息架构"，没有重建"视觉分离度"；且各次**只覆盖部分界面**

- **原因**：v3.3 重排 IA；v4 重排 IA（页签化）；v6-4 做 token + 控件库收口 + 面板重排。
  每一次都动"结构/颜色字符串"，**没有一次把"视觉层级与分离度"当交付物**。且 v6-4 明确承认
  popup 是**手写同结构**而非真复用控件库（`implement.md` 偏离 6，prd 侧 AC-8 也说"popup 仍是手写同结构（偏离 6）"）——
  于是 popup 的按钮/页签边框由另一套手写 CSS 决定，任何"面板改了按钮样式"的改动**不会传导到 popup**。
- **证据**：
  - popup 手写：`popup.html:38-44`（`.tab` 里 `border: 1px solid transparent` / `--svi-ctl-hover` 作边框）。
  - 面板按钮弱边框：`@4404-4414`（用 hover 色当边框）＋ `@4104/@4139`（preset/action 仅 0.08~0.12 白）。
  - 对比度实测（node 复算）：按钮底↔面板底 = **1.00**、按钮边框↔面板底 = **1.38**、DR 描边色↔面板底 = 2.95。
- **本次对策**：建一个**三处一致**的按钮/控件视觉规格（写进 `design.md`），并要求 popup **真复用**
  `extension/ui-controls.js`（v6-4 R1a 已把它抽成独立产物，popup 直接引即可，`implement.md:116-120`），
  停止手写同结构。AC3 的探针**必须同时覆盖三处**（页内面板 / popup / options），不覆盖即红（见 §4 P2）。

### D. 测试盲区：几何探针只测"溢出"，不测"可辨"；单测只扫文本/正则

- **原因**：唯一与布局相关的自动化是 `scripts/check-panel-overflow.js`，其判定是
  `scrollWidth > clientWidth`（`check-panel-overflow.js:89`）——**"没爆版"与"看得见"是两件事**。
  更糟的是它自己犯了 spec 明令禁止的错：`check-panel-overflow.js:123` 硬编码 `statsCells !== 11`
  （spec `quality-guidelines.md:716` 明写「**别断言硬编码的控件数量**」），
  于是它既发现不了边界问题，又会在加/减一个控件时假红。
- **证据**：`check-panel-overflow.js:14`（7 档宽度）、`:89`（唯一判据 scrollWidth）、`:123`（硬编码 11）。
  `test-browser.js:997-1013`（UI 断言全是 `hasModal` / 区块 id 存在 / 图标 svg **个数** / 面板无 emoji）——
  **没有一条读 `border` 类属性的值**。
- **本次对策**：新探针（§4 P1~P3）必须读 **computed style 的数值**（border-width/color 的对比度、
  元素的有效边界 box-shadow/outline），不接受 `className` 或"规则存在"；并**把 `statsCells===11` 这类硬编码改掉**。

### E. 修复与交付面脱节：`extension/` 是产物，popup/options 的改动路径与面板不同

- **原因**：面板（①）活在用户脚本里；popup/options（③④）由 `scripts/extension-src/` 构建生成。
  v6-4 虽然做到了 token 与控件 CSS 的**构建期注入**（`implement.md:131-134`），但 **popup 的 DOM/交互仍是手写**
  （偏离 6），所以"面板改了、popup 没跟上"是**结构性可发生的**，而且**当前门禁抓不到**（AC 只查 token 字节与 emoji）。
- **证据**：`implement.md:374-387`（偏离 6 逐字说明 popup 拿不到控件库实例、只能手写同名 class）。
- **本次对策**：AC8 要求 `extension/` 变更全部来自构建；再补一条断言：popup 引 `ui-controls.js`（或与之同源）
  且**三处按钮的 computed border 规格一致**（§4 P2）。

### F. 流程面：当前任务的 PRD 一度为 TBD（已由主会话补齐），且"计划先行"未被机械保障

- **本次对策**：AC10 要求本文件的「坑清单」逐条在本任务里有处置；`design.md` 必须等 `research/01~04` 回来后再写（prd.md:115）。

## ④ 本次必须规避的坑清单（可执行 · 可被测试或探针验证）

> 格式：**P# · 坑名 → 守卫方式（可执行） → 验收锚点（本任务 AC） → 若不做会怎样**。
> 每条都必须是"探针能读出数、断言能变红"，否则不得列入。

**P1 · 坑：把"边框存在"当成"边框可见"**
- **守卫**：CDP 探针枚举目标界面的每个 `button`/`[role=button]`，读 computed `border-width`/`border-color`/`background-color`，
  **计算 `border-color` 与 `background-color` 的 WCAG 对比度**，断言 `border-width > 0` **且** 对比度 `>= 3.0`
  **或**等价分离（`outline` / `box-shadow` 的非零 spread 且其颜色对比度 `>= 3.0`）。
- **反例必须被抓住**：`popup.html:40` 的 `border: 1px solid transparent`（`border-width>0` 但不可见）与
  `.svi-btn` 的 `#193945`（实测 1.38:1）**都必须变红**。
- **验收锚点**：AC3（并补"可见性门槛"这一句，否则 AC3 会放过 transparent）。
- **不做会怎样**：重演第 4 轮 —— 断言全绿，用户仍说"没有边框"。

**P2 · 坑：只验页内面板，三处界面各改各的**
- **守卫**：同一条 P1 探针**跑三遍**：页内模态 / 扩展 popup（真标签页打开 `extension/popup.html`）/ options 页；
  输出**逐按钮属性表**并断言三处的"按钮边界规格"集合一致（同一 kind 的按钮不得一处有框一处无框）。
- **验收锚点**：AC3（三处）＋ R6。
- **不做会怎样**：popup 将永远是手写第二套（`implement.md` 偏离 6），面板修了它不修 → 下次投诉换成"popup 没边框"。

**P3 · 坑：把"点外部关闭"当"有关闭入口"**
- **守卫**：探针先记录 `.svi-panel-card` 无 `show`；点 pill 使 `show` 出现；然后**只在面板内部**寻找一个显式关闭控件
  （`[data-svi-close]` 或 aria-label 含"关闭"的 button），点击它；断言 `show` 消失且**探针从未派发过面板外的点击**。
- **验收锚点**：AC1（原文已写"全程未点击面板外部"）。
- **不做会怎样**：`.svi-panel-card` 至今**零关闭控件**（`@13339-13347` 实测 header 只有标题 + 徽章）；
  用户会继续报"没有关的地方"。

**P4 · 坑：容器里留着原生 `input[type=color]`**
- **守卫**：探针断言 `.svi-panel-card` 内 `input[type="color"]` 计数为 `0`；并把该断言**扩到页内模态**——
  若 `design.md` 决定保留自绘色板，则断言全仓（用户脚本 + `extension/` + `scripts/extension-src/`）的
  `type: 'color'` / `type="color"` 出现次数为 `0`；若保留例外，例外必须在 `design.md` 明写并被用户接受。
- **补充**：还需断言"取色之后仍能用**显式控件**关闭面板"（与 P3 合并执行一次：取色 → 关闭）。
- **验收锚点**：AC2。
- **不做会怎样**：`.svi-color-input-native`（`opacity:0; inset:0`，`@5000-5007`）会继续让"点色块 = 弹原生对话框"，

**P5 · 坑：靠"人工看截图"发现观感缺陷（`panel-shot.js` 教训）**
