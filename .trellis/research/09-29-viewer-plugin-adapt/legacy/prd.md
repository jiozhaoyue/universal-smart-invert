# 浮图秀类看图插件的放大浮层反色适配 + 不可逾越技术边界实测划界

## Goal

对「看图/放大镜」类浏览器插件（浮图秀、Imagus-Reborn、Hover Zoom+ 等）做**实测适配**：判定放大浮层
出现后本脚本是否反色、走哪条路径反色、失败在哪一步；并把用户提出的三类担忧
（网络未交付、机器卡顿、媒体未加载/像素不可得）连同实现期新发现的项，**逐条划界为「真无解」与「可解」**，
可解项落实现，真无解项给出诚实且可复核的说明。

## 背景（用户 2026-09-29 原话，作为需求真源）

> 对浮图秀等开源插件做适配，看放大后是否也能反色。
> 讲清楚无法逾越的技术问题：网络，和电脑比较卡，在元素未完全加载，拿不到，就没法反色，
> 以及媒体元素，没加载就是白色区域，这个也没法解决。
> 找出有哪些是，说明，或尝试解决。

要点拆解：
1. **要适配**（不是只写文档）—— 放大后的浮层也要能反色。
2. **要划界**（找出有哪些「是」真无解的）—— 用户的担忧是候选清单，不是结论；须实测裁决。
3. **要说明或尝试解决** —— 真无解给说明，可解给实现。

## 前置事实（开工前已核实，构成本任务的起点而非结论）

| 跨域 iframe / 闭合 Shadow Root | **已覆盖**：扩展 `all_frames:true`（`extension/manifest.json`）；`attachShadow` 幂等补丁 + 注册表按 host 解析闭合根内媒体（`:5589`、`:8405`） | 仅需实测确认 |
| 媒体晚加载 → 拿不到 | **已接上**：档 B/C 登记 pending + `attachPendingWake` 一次性 `load` 监听 → 清 `data-svi-checked-src` 后按全管线重判（`:9282`-`:9338`） | 仅需实测确认 |
| 放大浮层媒体即时反色 | **部分**：v3.1 R6 变更快路径仅在 `decisionBySrc` **已命中**时同步应用（`:8292`）；浮层 src 通常是**原图 URL**，与缩略图 URL 不同 → 大多不命中 | **是** |

| 媒体未加载 → 白区 | 已有 v5.5 `pendingMask` 遮罩，但其动作是 `visibility:hidden`（**藏元素、露背后**），白底站点上白区仍在；文档级黑底只在 `bgReplace` 站点生效 | **是（用户 2026-09-29 追加，要求必须解决）** |

## Requirements

### R1 — 实测划界（本任务的第一性产出）
对下列三类目标实测并产出「现象 → 机制根因 → 归属」三分表：

- **真机插件**：`hababr/Imagus-Reborn`、`extesy/hoverzoom`（Hover Zoom+）—— 均为开源、可下载未打包加载。
- **合成浮层夹具**：按浮图秀 / 看图类插件的典型 DOM 形态构造（浮图秀在 Chrome 应用商店分发且闭源，
  **无法加载未打包版**）。夹具须覆盖至少：`<img>` 浮层、`background-image` 浮层、
  `position:fixed` + 高 z-index 覆盖层、闭合 Shadow Root 内浮层、`<canvas>` 浮层。
- 每条结论**必须附可复核证据**（CDP 探针输出 / bench 场景断言），不得只写推断。

### R2 — 归属判定：真无解 vs 可解
每条候选须落入且只落入三类之一，并写明理由：

- **真无解**：浏览器不提供任何可见/可钩的接缝（例：媒体字节从未到达；元素从未进入文档；
  内容绘制在脚本不可达的合成层）。
- **已覆盖**：现有机制已处理（须给 file:line + 实测证据）。
- **可解未覆盖**：存在接缝但当前代码没接（须给可执行的修复方案）。

### R3 — 可解项实现
对判定为「可解未覆盖」的项落实现。**接受「实测后判定某项不值得改」作为合法结论**，
但必须写明放弃理由（成本/收益/风险），不得静默丢弃。

#### R3.1 — 遮罩档改造：从「藏元素」改为「深色占住盒子」（用户 2026-09-29 追加）
用户原话：
> 我就说在未加载前加上遮罩，挡住，调查可以做到与否，必须解决这个问题，就像背景防闪白功能，
> 强制遮住，以及这个功能也和所有功能一样，可以按站点来开关

**现状核查（已实测，见 `research/01-overlay-probe.md` §8）**：
- 「按站点开关」**已存在**：面板「本站强制启用 / 取消」→ `siteOverrides[host].pendingMask`（`:16281`）；
  全局三档 `flashGuardLevel: 'off'|'document'|'media'`（`:266`）。
- **但现有 media 档的动作是 `visibility:hidden`（`:5184`）—— 把元素藏起来、露出背后**。
  白底站点上背后仍是白（文档级黑底只在 `prof.bgReplace === true` 时生效，`:16620`）
  → **白区并未消失，用户的问题没被解决**。

**要求**：media 档在「元素尚未就绪」期间，**用深色占住该元素的盒子**（而非隐藏它），
使白区变成深色；元素就绪或判定完成后**自动摘罩**。守既有硬约束：
- 复用现有 `data-svi-pending` 属性门与 `settle/settleAll/escape` 生命周期，**不新增状态字段**；
- 打标仍为**同步热路径且不读布局**（不调 gBCR / gComputedStyle）；
- 颜色只取 token（`var(--svi-bg)` 一类），**不得出现字面量颜色**（既有硬规则）。

**明确不做（原理下界，须写入文档不得回避）**：
- 元素**连布局盒都没有**时（无 CSS 尺寸、无 HTML width/height、图未到 → 尺寸未知）→ 无盒可占，遮不住；
- 用户脚本形态的**首屏**不遮（`@run-at document-end`，元素已渲染；真·首帧前遮罩只有扩展形态可行）——
  此约束仓内已文档化，本次**不改变**它。

#### R3.2 — 跨 URL 视觉同一性继承（解 G2 与 G1 的常见路径）
浮层继承「它所放大那张缩略图」的既有结论，从而**免去等待原图字节**与**免去跨域取图**。
- 继承结论必须标 `provisional: true`（复用既有可升级语义，`:8126`），真像素到达后升级；
- **防误判硬约束**：关联目标或浮层本身是 `<video>` 时**不继承**；无信号命中则不继承（宁可慢不可错）；
- 新增的「最近悬停媒体」状态**仅内存、per-tab、有界、绝不持久化**；`document.hidden` 时停记。

#### R3.3 — 扩展形态加 service worker（解 G1 的残余）
用户 2026-09-29 明确选择「三项全做（含 SW）」，并明示「架构不管，随时可重构」。
- 新增 `background` service worker + `host_permissions`，使扩展形态获得跨域取图能力；
- **必须实证**：`web-ext lint` 仍 0 errors；Chromium 与 Firefox 两侧都能加载并生效；
- **必须实测权限提示是否变化**：现行 `content_scripts.matches` 已含 `<all_urls>`，
  该权限提示**可能本来就在**（若如此则本次不新增任何用户可见权限）；**不得凭推测写结论**，
  要给出可复核的观测方式与结论；
- `build-extension.js` 产出 SW 文件；**不得为两引擎分叉产物目录**（既有硬规则）。

#### R3.4 — 真机插件实测（用户 2026-09-29 确认「做」，并已预授权联网拉源）
- `git clone` `hababr/Imagus-Reborn`、`extesy/hoverzoom` 到 `dev/tools/viewer-plugins/`（`.gitignore:53` 已覆盖）；
- 验证真实插件的浮层 DOM 形态是否落在夹具覆盖范围内；
- **裁决继承信号 S1/S2/S3 哪条真命中** —— 继承信号链的取舍必须由此决定，不得凭猜。

重点验证的一条假设（**假设，不是结论**，R1 实测裁决）：
> 浮层反色的真实瓶颈是**时延竞争**而非能力缺失 —— 新插入的浮层媒体要经过
> `MutationObserver` 100ms 去抖（`:8219`）→ `IntersectionObserver` 一轮 →
> `decideImage` → 首次无缓存时走 `gmFetchBlob` **一次网络往返**取原图，
> 合计常达数百毫秒；而悬停浮层的存活期可能更短，于是用户看到「闪一下没反色」。
> 若实测成立，可解方向是让浮层走**免网络**的判定路径（同图不同 URL 的视觉同一性继承 / 同步非去抖通道）。

### R4 — 诚实说明（真无解项也要交付）
真无解项须在仓库面向用户的文档（README 及其 FAQ 段）给出可读说明：现象、根因、
「为什么这是浏览器的下界而不是本脚本的缺陷」。**不得把已覆盖项写成无解来省事，
也不得把无解项包装成已解决。**

### R5 — 不破坏既有契约（硬约束）
本任务的一切改动必须遵守仓库既有硬规则，尤其：
- 运行时状态 per-tab 内存、**绝不持久化**；只有 `svi:*` 键走 `Store`。
- 图片决策 **decide-once**：相同输入不得在两次 pass 间翻转；同一 `src` 快照稳定。
- 禁止 `html`/`body` 整体滤镜；禁止 `innerHTML` 接动态数据；禁止自动遥测。
- 观察器须去抖 / 空闲预算 / `document.hidden` 时暂停。
- 用户脚本与扩展通过 `dataset.sviOwner` 握手共存；改 `@version` 须同批重建 `extension/`。
- 界面字符串中文、标识符 ASCII、`// ===== N. =====` 分段横幅、面板 UI 只经 `SviControls`。

### R6 — 收尾产物
五绿门禁全绿 + `build-extension` + `pack`；`@version` bump；README / spec 沉淀；
**提交后必须推送 `origin main`**（本仓硬规则：只提交不推送视为未完成）。

- 为某个具体闭源插件写站点专用硬规则（`浮图秀` 的 URL 规律属逆向产物，不稳定，不做）。

- 视频流的浮层适配（本任务只覆盖图片/背景图/canvas 浮层；视频另论）。
- 重做区域分割（0.6 内核）或 MASK 契约 —— 契约已冻结，任何改动须回规划。
- 扩大改动面到 UI / 面板（那属 09-28-ui-overhaul 任务）。
