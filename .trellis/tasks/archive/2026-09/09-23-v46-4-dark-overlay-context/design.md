# v4.6-4 技术设计：暗色遮罩容器场景

## 1. 场景建模

```
<div class="profile-hero" style="background: rgba(0,0,0,.6)">   ← 暗色蒙层（在图片之上）
    <img src="bright-cover.jpg">                                ← 原图像素亮
</div>
```

- 图片自身像素：亮 → 现有管线判 `invert`
- 实际可见合成：亮图被 60% 黑蒙层压暗 → 视觉已"够黑"
- 反色后：亮变暗 → 叠在暗蒙层上 → 合成后**更暗/发灰/糊**，且用户明确说"视觉还好"却被改坏

即：**判定依据（原图像素）与观感依据（合成像素）不一致**。

## 2. 检测策略（只用本地信息）

按可靠性排序，逐级降级：

1. **祖先覆盖层检测（主路径）**
   - 沿祖先链（≤3 层，可配）查找同时满足的节点：
     - 几何上覆盖目标（`getBoundingClientRect` 包含目标 ≥ 阈值覆盖率，如 80%）
     - 本地已知的暗色半透明填充来源（以下任一）：
       - 自身 `background-color`（含 alpha<1 且亮度低于阈值）
       - `background-image` 为渐变且计算样式含暗色
       - `::before` / `::after` 计算样式（`getComputedStyle(el, '::after')` 的
         `background-color` / `content` 非 none 且覆盖目标）
       - 兄弟/绝对定位蒙层节点（`position:absolute/fixed` 且覆盖目标且背景暗）
     - 层叠顺序：蒙层需在目标**之上**（比较 z-index / DOM 顺序 / `position` 判断）
2. **合成采样（次路径，更强但更贵）**
   - 若可（同源、已解码）用 canvas 以目标**实际显示尺寸**绘制，先绘制各层背景色再绘制图片，
     得到**合成均值亮度**；合成亮度已足够暗 → `keep`
   - 跨域/taint 时降级到策略 1
3. **兜底**：无任何本地证据 → 沿用既有管线（保守，不新增行为）

## 3. 契约

| 契约 | 说明 |
|---|---|
| C1 | 新增原因码 `masked-dark`（可审计，出现在决策报告/统计） |
| C2 | 只允许在"高置信"时改变结论；不确定 → 沿用旧结论（不新增误判） |
| C3 | 性能预算：祖先检查 ≤3 层、结果按元素键入快照缓存、不触发强制同步布局多于 1 次 |
| C4 | 浅色蒙层（白/亮渐变）**绝不**触发；纯黑不透明蒙层下图片本身不可见 → 视作 `keep`（已不需处理） |
| C5 | decide-once：结论入快照，同输入不翻转 |
| C6 | 图片引擎与背景替换引擎（bgr）均接入同一纯函数 `maskedDarkContext(el)` |

## 4. 纯函数与测试矩阵

```
maskedDarkContext(el) -> { masked: bool, reason: 'ancestor-veil'|'composite-sample'|'', luminance: n }

fixture 对照（本地 HTML，四案例）：
  A 亮图 + 黑 60% 蒙层（覆盖 100%）   → masked=true  → keep
  B 亮图 + 无蒙层                     → masked=false → invert
  C 亮图 + 白 60% 蒙层                → masked=false → invert
  D 暗图 + 黑 60% 蒙层                → masked=false → keep（原本就 keep）
```

## 5. 风险与回滚

| 风险 | 缓解 |
|---|---|
| 过度保守 → 大量该反的图不反（比误反更伤） | 上线初版只处理"覆盖率 ≥80% + 明确暗色 alpha 层"；加统计计数观察；保留 `state.maskAware` 开关（默认 true，可关） |
| `getComputedStyle(el,'::after')` 成本 | 仅当策略 1 其它条件先成立时才查伪元素；结果缓存 |
| 布局抖动 | 一次性批量读取 rect（先读后写），不穿插写操作 |
| 与子任务 1 的本地优先改动冲突 | 二者都在 `decideImage` 前置证据层，需约定：遮罩判定优先于像素判定（更接近"所见"），但均低于手动覆盖 |

## 6. 优先级位置（必须明确）

```
手动覆盖 > 元素规则 > 遮罩上下文(新) > 快照 > 学习 > 种子 > 策略门 > 像素
```

遮罩上下文置于"快照"之上，因为它是**每元素几何相关**的实时事实，
但必须入快照以避免 decide-once 冲突（首轮算一次，之后复用）。
