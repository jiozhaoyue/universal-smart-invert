## 定位

v5 把插件从「反色器」扩成页面媒体治理层（六动作 + 采集回路 + 保护机制）。v6 解决的是
**反色粒度**问题：现有整图反色只有「全反」与「全不反」两个挡位，对「一张图里既有浅底
又有不该动的内容」这类图两边都不对 —— 白底 PPT 截图里嵌的彩色照片会被反成负片；深色
代码截图里的白色高亮块会继续刺眼。

v6-1~v6-3 把判定单位**从整图下沉到连通区域**，产出第三条路；v6-4 把表现层做全量同源重构；
v6-5 补齐扩展形态的自动化测试与交付产物（CRX）。

## 技术前提（已实测，非推测）

本任务的关键架构选择**不是推演出来的，是探针实测的**。两个一次性探针：
`dev/probe-partial-backdrop.js`、`dev/probe-partial-tracking.js`（真 Chrome + CDP +
元素截图 + ffmpeg 解 raw RGB 采样像素；7 用例 × img/video 两轮）。

| # | 命题 | 实测结果 |
| :-- | :--- | :--- |
| P1 | `backdrop-filter` 与 `clip-path`/`mask-image` 同元素时，裁剪能否限制反色范围 | **能**。`circle()` / `inset()` / `polygon()` / `url(#clip)` / `mask-image: radial-gradient()` 五种形态均「中心反色、角落原色」 |
| P2 | 视频上是否同样成立 | **是**。video 用例七项结果与 img 逐项一致（`currentTime` 推进、未 paused） |
| P3 | evenodd 挖洞（外框 ∖ 内区）能否用作「选区保原色、其余反色」 | **能**。中心（洞内）原色、四角（环上）反色 |
| P4 | `clipPathUnits="objectBoundingBox"` 是否可用于自动跟随元素缩放 | **是**（经 `clip-path: url(#id)` 引用） |
| P5 | `backdrop-filter` 是逐帧重采样还是静态快照 | **逐帧重采样**。白/黑每 0.5s 交替的视频，采样值同步交替 |

**由此确定架构**：走 `backdrop-filter` 覆盖层，**不做**用户最初设想的「画中画克隆层」。
克隆层对 `<img>` 可行，但动图克隆会从第 0 帧重播、`<video>` 克隆要同步 `currentTime`/
`playbackRate`、跨域视频克隆因缺 `crossorigin` 直接失败。backdrop-filter 在合成器层面采样、
**不读像素**，故跨域图、跨域视频乃至 DRM 视频同样可反色。

## 约束

- **单文件真源**：`universal-smart-invert.user.js` 是唯一权威源，`extension/` 为生成物，绝不手改。
- **无双重滤镜**（D2 的根据）：现有反色滤镜是 **5 段链**
  `invert(1) hue-rotate(180deg) brightness(0.92) contrast(0.90)`（见
  `universal-smart-invert.user.js` 的 `--svi-img-filter`）。`brightness`/`contrast` 在近白端
  会钳位，导致「反色再反色」回不到原色（彩色照片有色偏与暗部细节丢失）。子任务**不得**
  改用「overlay 叠加在已反色元素上」的双重滤镜路线。
- **零外部依赖 / 离线自持**：不得引入 CDN、不得引入 npm 运行时依赖、不得内联 ML 模型。
  自动分割必须纯统计（现有明度/饱和度特征）+ 形态学，不依赖语义分割。
- **零遥测**：纠正数据全本地；网络出口与 v5.0.0 逐条一致，规则包导入仍是唯一手动联网通道。
- **性能预算不放宽**：视频单帧检测仍 <0.01ms 量级；图片单张 <1μs 量级；新增判定不得进入热路径。
- **默认保守**：部分反色默认关；首次启用给出说明。
- **形态差异必须显式**：任何依赖「早于首帧」的能力必须分形态说明，不得让用户以为开关坏了。
- **注释与文档全中文**，代码标识符/命令输出/专有名词除外。

## 非目标

- 用户手动绘制选区（多边形 / 套索 / 笔刷）—— D1 已排除。底层几何管线仍要做，但输入源是
  自动分割的输出，不是用户绘制。
- 魔棒自动吸附内容边界（需读像素且跨域直接失效）。
- 语义分割 / ML 模型 / 云端推理。
- 云端聚合、自动上报。
- 内容指纹维度的纠正泛化（D4 已选 stem 维度）。

## 已知风险与未决项（子任务 design 必须正面处理）

1. **backdrop root 截断**（最高风险）：媒体元素的祖先若带 `filter` / `opacity<1` /
   `mix-blend-mode` / 自身 `backdrop-filter`，覆盖层的 backdrop 会被截断，采样不到画面
   → 反色**静默失效**。探针只验了干净 DOM。需运行时祖先链探测 + 明确降级提示，
   且探测**不得进入热路径**（只在覆盖层建立时探一次，结果缓存）。
2. **坐标换算**：自动分割输出的是归一化内容盒坐标，与 `object-fit` letterbox、
   CSS `transform`（含祖先）、`zoom`、`background-size/position` 的映射需逐项处理。
3. **视频/GIF 帧间失配**（D5 的代价）：掩码按首帧/场景跃变/心跳重算，帧间沿用；场景
   渐变（非跃变）时掩码会滞后。GIF 无可用场景 API，只能低频心跳。需预算上限与
   失配时的降级策略。
4. **掩码内存与缓存**：每张图一份掩码。需缓存键与淘汰策略，避免长页面堆积。
5. **与元素级 filter 的互斥**：图片特效模式（`luma`/`grayscale`/`sepia`）、视频画面调节
   （`videoTune`）都是元素级 `filter`，与 D2 的「本体无 filter」直接冲突，需定义优先级与
   面板提示。
6. **全屏 / PiP**：video 进全屏或画中画后覆盖层脱离，需 `fullscreenchange` /
   `enterpictureinpicture` 处理。
