## 阶段 1 — 分区判定管线 ✅ 完成

- [x] 在 `analyzeSrc` 的既有链路上增加**可选的网格采样分支**：仅当第 4 参 `wantGrid` 为真时
      以 `regionGridN` 采样并在返回值上附带 `grid`（缺省 `false` 时采样尺寸与分母不变）
- [x] 逐格特征：`regionCellGrid(data, size, prefsState)` 把 `N×N` 采样切成 `N×N` 格，
      逐格跑**同一套单像素谓词**。**做法与计划不同**：不是逐格调 `evaluateImagePixelStats`，
      而是共用被抽出的谓词本体 —— 见「偏离 4」
- [x] 逐格二值化谓词：**直接复用整图门槛，不做"更宽松的逐格门槛"**。
      依据：逐格输入不是单点采样而是 `drawImage` 的**区域平均**，噪声本就低于预期；
      且放宽门槛会破坏「逐格与整图同源」这条可断言的性质。去噪交给阶段 2 的形态学
- [x] 整图统计**从网格聚合**：`regionGridRatio(cells, opaque)` —— 分母是**不透明格数**
      （与整图 `lightRatio` 同口径；用总格数会让含透明区的图系统性偏低）
- [x] 单测：全浅 / 全深 / 左浅右彩 / 棋盘四种人工网格 + 谓词抽取等价性 + 分母口径

**落地位置**：谓词抽取在 section 12（`buildLightTestCtx` / `classifyLightPixel`），
逐格判定在 section 12.5（`regionCellGrid` / `regionGridRatio`）。

## 阶段 2 — 形态学 + 连通域 + 面积门 ✅ 完成

> **复选框回填说明**：本阶段的代码与单测在 2026-09-25 的会话里已落地并通过，
> 但当时未随做随勾（违反全局规则 §4.5），此处由后续会话**逐条对着代码与实测结果核对后**补勾，

> `regionCarve`、以及「v6.0 阶段 2 单测」块。

- [x] `gw×gh` 上的 3×3 形态学：`dilate` / `erode` / `close` / `open`
- [x] 连通域标记（显式队列迭代 BFS，8 邻域，与形态学邻接度一致）
- [x] 最小面积门：面积 < `minAreaRatio * gw * gh` 的连通域**跟随邻域多数**
      （实现方式：不足面积的块不进 `big` 表，carve-color 里它们跟着多数被反色、carve-light 里跟着多数不反色）
- [x] **默认方向实现**（`design.md` §4 步骤 ④）：`invert = 全图 ∖ (面积达标的非 lightLike 连通域)`
      —— 用「白底黑字密集图」验证：**不产生碎裂掩码** ✅，且（裁决后）**不抠掉文字** ✅
      （实测 0/60，见偏离 5）
- [x] 对偶极性 `carve-light` 的实现与切换条件（`coverage > 0.5` 判 carve-color，否则 carve-light）
- [x] 单测：形态学四算子各自的行为（含边界复制回归）；面积门边界（N=32 的 25 / 36 格两侧）；
      方向正确性（白底黑字图产出的是**大块连续**而非细碎）；**先闭后开反例留档**断言

**补充（原计划未写、实测逼出来的两条）**：
1. **形态学必须施加在「要被连通域分析的那个集合」上**，而不是笼统施加在 `cells` 上 ——
   对 carve-color 是「非浅色」集，对 carve-light 是「浅色」集（初版搞反过）。
2. **腐蚀的边界复制约定**（越界取最近边缘格，等同 `scipy.ndimage` 的 `mode='nearest'`）——
   按背景处理会造出 0 值边界环，那圈会被面积门当成大特征抠掉，后果是**图片最外一圈永不反色**。
   见偏离 6。

**验证**（实测）：`node --check` → 通过；`node test.js` → 全绿（阶段 2 块）；
`node test-browser.js` → 29 场景 100% 通过（阶段 8 统一复跑）。

## 与计划的偏离记录

> 格式：`偏离 N — 原计划 / 实际 / 原因`

**偏离 1（阶段 0）— 契约校验从 I1–I6 扩到 I0–I7。**
原计划阶段 0 只覆盖 I1–I6（I7 归 v6-2 的渲染等价断言）。实际实现时补上了
**I0（契约版本）**、**I7 的位图分支**（`expr.kind === 'bitmap'` 且长度与灰度取值正确），
并把 I8（矢量可行性 ⟺ 非位图）明确标注为阶段 4 交付。
原因：`validateRegionMask` 是 v6-2/v6-3 消费任何掩码前的第一道闸，版本号漏检等于契约漂移
无法被发现；位图分支的取值口径（0/255）也是契约的一部分，不下断言就会漂。

**偏离 2（阶段 0）— 中间带占位返回整图结论，而非空 `region` 掩码。**
原计划阶段 0 的 `buildRegionMask` 对门 1 未命中的中间带返回一份空 `region` 掩码占位。
实际改为**返回整图结论**（`whole` / `none`）。
原因：空 `region` 掩码的 `coverage === 0`，直接违反不变量 I5（region 要求
`coverage ∈ (0,1)`），会让契约在阶段 0 就自相矛盾。返回整图结论既满足全部不变量，
又恰好等于 v5.0.0 行为，符合「阶段 1–4 落地前一律退化为整图」的安全回退。

**偏离 3（阶段 0）— 发现项目规范对设计的三条硬约束，已回填 design §2.2。**
读 `.trellis/spec/frontend/quality-guidelines.md` 后发现：判定谓词必须经 `getEvalPrefs()`
（站点级阈值覆盖要透传）、图片与视频是两套阈值字段、`loadState` 侧的默认值必须内联字面量
（`REGION_DEFAULTS` 的 `const` 会撞 TDZ）。前两条原设计未写，第三条原设计未写且已实际
影响 `loadState` 的写法。已回填 design §2.2 并在实现中遵守。

**偏离 4（阶段 1）— 变更边界声明漏判了一处本地重构：必须抽出单像素谓词。**
原变更边界写「是否需要本地重构：不需要」。**这个判断是错的**，
`evaluateImagePixelStats` 末尾有聚合级守卫：

```js
if (opaqueCount < 8) return { isLight: false, lightRatio: 0 };
```

单像素输入的 `opaqueCount` 恒为 1，**逐格直接调用它必然全部返回 `isLight: false`**，
逐格判定会彻底失效。三条出路：

| 出路 | 取舍 |
| :--- | :--- |
| 逐格自己写一份谓词 | **违反**规范 v5.4 §2「两条采样路径必须共用同一判定函数」，必然漂移 |
| 放大采样让每格 ≥8 像素 | 采样尺寸失控（需 N≈48 才够），且仍与整图口径不同源 |
| **抽出单像素谓词，两处共用** | 一次 ~35 行的纯抽取，是唯一同时满足「同源」与「逐格可用」的做法 |

**实际做法**：把单像素判定抽成 `buildLightTestCtx(prefs)` + `classifyLightPixel(r,g,b,a,ctx)`
（三态：`-1` 透明完全不参与 / `0` 计入不透明但非浅色（含被屏蔽）/ `1` 浅色），
`evaluateImagePixelStats` 改为调用它。抽取是**逐字保留语义**的：
透明像素不进 `opaqueCount`、被屏蔽的**进** —— 这个区别直接决定分母，改了就改结论。

**行为不变的证明**：抽出谓词后**先单独跑一遍四绿门禁**（`node --check` / `test.js` /
`test-browser.js` 29 场景 / build+pack）确认全绿，**再**往上加逐格判定 ——
不让「重构未改变行为」与「新增功能」混在同一次验证里。另补了谓词等价性单测：
手工按谓词逐像素计数必须与聚合函数的 `lightRatio` 逐位一致。

**是否需要用户裁决**：判定为否。这不是扩大改动面，而是在两条已有约束
（「复用现有特征口径不新增阈值定义」与规范 v5.4 §2「必须共用同一判定函数」）下
**唯一可行**的实现方式；另两条出路一条违规、一条不可行。已如实上报。

**偏离 5（阶段 2）— 形态学顺序：原设计的「先闭后开」被实测证伪，裁决改为「先开后闭」。**

原设计（design §4 ⑤ 与代码注释）写的是：闭运算填小洞 → 开运算去细碎；并声称
「3×3 开运算的**厚度门**会把 1~2 格厚的白底黑字细笔划挡在特征集之外」。

**实测把这个声称打穿了**：16×16 网格上 5 条 1 格厚文字带，**先闭后开被抠掉 60/60 格**。
根因：闭运算的第一步是**膨胀**，它把行距 ≤2 格的相邻文字带合并成一条实心带，之后的开运算
只能腐蚀、不能拆开 —— 于是整片文字区成了「一块大特征」被抠掉，文字保持原色，
再整图反色后**文字消失在深底上**（正是用户最不能接受的那种错）。

| 顺序 | 白底黑字图结果 |
| :-- | :-- |
| 先闭后开（原设计） | 抠掉 60/60 → 文字消失 ❌ |
| **先开后闭（裁决采用）** | 抠掉 0/60 → 覆盖率 1.0 → 门 2 → 整图反色 → 文字变白、可读 ✅ |

先开后闭还让代码注释里那句「厚度门挡住细笔划」**第一次真的成立**（先开后，细特征在腐蚀步就被抹除）。
在 test.js 里留了一条**反例断言**（先闭后开会把 5 条文字带合并成 >5 行实心带），谁把顺序改回去都会立刻炸。

**是否需要用户裁决**：**是，已裁决**（2026-09-25，用户选择「改为先开后闭」）。

**偏离 6（阶段 2）— 腐蚀的边界约定必须是「边界复制」，不能按背景处理。**

`close = erode(dilate(...))` 里，若腐蚀把越界格当 0，则触边对象会被收缩，
并在 `erode(dilate(F))` 里造出一圈 **0 值边界环**；那一环在 16×16 下面积 60 格，
会被面积门当成「特征大块」抠掉 —— 后果是**图片最外一圈永远不被反色**（白底幻灯片出现一圈白框）。
实测抓到后改为**边界复制**（越界取最近边缘格，等同 `scipy.ndimage` 的 `mode='nearest'`）：
掩码语义上图片边缘不是「背景」，边缘格就是边界。
test.js 的形态学断言里留了「含边界复制回归」的用例。

**是否需要用户裁决**：判定为否（纯实现缺陷的自纠，行为可断言、可回归）。

**偏离 7（阶段 3）— 双门阈值：AC 写的 0.90/0.10 改成 0.97/0.03（= 1 - 面积门）。**

这是本片**唯一一处改了 PRD 验收标准数值**的地方，全过程与理由如下。

**① 起因（第一次裁决）**：test.js 的实测 B 显示「浅底 + 5×5 嵌入块」抠完覆盖率 0.902，
被 0.90 的门吞掉判回整图 —— 嵌入块仍被反色。上一版注释把这一例记作「**门 2** 的 0.90」，
我据此向你提问，你选择「门 2 上界放宽到 0.97，门 1 保持 0.90」。

**② 实测更正**：改完门 2 后复跑，同一例**依然**判回整图。逐层打印中间量才发现真正的卡点是
**门 1**：该图浅色占比 0.902 ≥ 0.90 → **进分割之前**就被短路成整图反色。
上一版注释与日志的归因是错的，我第一轮提问沿用了这个错误前提 —— 已更正（test.js 实测 B
的注释与日志现在直接打印浅色占比与抠后覆盖率两个数，谁都能一眼看出卡在哪一道门）。

**③ 你明确表示数值交由主代理判定**（原文：「我不知道，数值我真不知道」）。故由我按工程口径定：

```
门 1 上界 = 门 2 上界 = 1 - minAreaRatio = 0.97
门 1 下界 = 门 2 下界 =      minAreaRatio = 0.03
```

理由三条：
- **自洽**：抠掉的量小于「最小特征块」⟺ 一格都没抠掉（任何存活特征块都 ≥ 面积门），
  所以「不值得分割」与「不值得挂掩码」本就是同一个判据，两门用同一对阈值不是巧合而是同源；
- **主场景下限从 10% 降到 3%**：PRD 背景点名的「PPT 里嵌彩色照片 / 二维码 / 品牌 logo」
  这类内容通常小于图面积的 10%，停在 0.90 就必然被整图反色 —— 功能等于白做；
- **代价已实测**：浅色占比 0.90~0.97 的图多付一次约 **0.04ms** 的分割（N=16 典型路径），
  距 PRD 的 <1ms 量级预算还有两个数量级。

**④ 可逆性**：两个阈值在 `REGION_DEFAULTS` 里由 `REGION_MIN_AREA_RATIO` **硬派生**
（不是两处独立的字面量），改那一个常量即整体回退到 0.90/0.10 口径；
`git revert` 本提交亦净。

**⑤ 与 PRD 的关系（必须如实记录）**：PRD R5 的 AC 原文是「整图浅色占比 ≥ 90% 或 ≤ 10%」。
本片实现**偏离该数值**，属已知偏离，已在交付汇报中显式上报；PRD 正文未改（用户书写的
验收标准不代改，留待你决定是否同步修订）。

**是否需要用户裁决**：**是，已裁决**（用户授权主代理定数值；方案与代价已在汇报中列出）。
