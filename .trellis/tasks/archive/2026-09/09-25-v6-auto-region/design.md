# Design: v6-1 自动区域分割内核

> 本文件是 v6-2 / v6-3 的**契约依赖**。§3 的 `RegionMask` 冻结后，下游只消费不修改。

## 1. 边界

**做**：把「整图一次判定」下沉为「分区判定」，产出区域掩码 + 冻结契约 + 双性能门 + 缓存。

**不做**：
- 不渲染任何东西（不碰 DOM 观感，不建覆盖层）—— 那是 v6-2。
- 不做纠正交互（v6-3）。
- 不新增解码路径（复用现有链）。
- 不进入热路径（不新增帧内同步查询）。

**本片对用户可见的变化：零**（默认关闭，且关闭时不产生任何分割调用）。

## 2. 现状接缝（实读的代码事实）

| 事实 | 位置 |
| :--- | :--- |
| 统一解码链：本地采样 → `opaqueCount >= 8` 即用 → 否则计 `taintFallbacks` 并走 `gmFetchBlob` → blob 解码 | `analyzeSrc(src, drawable, prefsState)` @5980 附近 |
| 本地采样：离屏 canvas `size×size` + `drawImage` + `getImageData`，跨域抛错 | `sampleDrawable(drawable, size = 8)` @5897 |
| blob 回退采样：`createImageBitmap` 失败 → `URL.createObjectURL` + 临时 `<img>` | `decodeBlobSample(blob, size = 16)` @5913 |
| 图片双特征判定（`imgLumCutoff` 默认 180 + 色卡容差 + 原色屏蔽） | `evaluateImagePixelStats(data, s)` @5811 |
| 视频双特征判定（`lumThreshold` 默认 210，`avgSaturation <= 0.22`） | @5222 `isWhiteSlide` |
| 写点收口（属性门 + 手动结论幂等占优） | `applyInvertState` @2481 → `arbitrate` @~2430 |
| 动作注册表 | `ACTIONS` @~2010 |
| 计数器 | `StatsManager.count(name)` |
| 导出契约 | `window.__svi` @13414+ |
| 缓存上限先例 | `ImageFxEngine.lruMax = 200` @7930 附近 |

### 2.1 已发现的既有不一致（本片必须处理，不得扩大）

| 不一致 | 影响 |
| :--- | :--- |
| 本地采样用 `size=8`，blob 回退用 `size=16` | 同一张图走不同解码路径会得到**不同的降采样结果**，判定阈值相同但像素基数不同 |
| 图片判定阈值集（180 + 色卡）与视频判定阈值集（210 + 0.22）是**两套** | 区域分割必须明确复用哪一套，否则「部分反色」与「整图反色」的边界会不一致 |

**决策**：区域分割**复用图片路径的判定谓词**（`evaluateImagePixelStats` 的特征口径），
并在设计中只使用一个采样尺寸 `N`（不再出现 8/16 分叉）。视频的区域分割沿用同一谓词，
但**采样尺寸由视频自己的调度决定**（见 §7）。

### 2.2 项目规范带来的三条硬约束（读 `.trellis/spec/frontend/quality-guidelines.md` 后确定）

| # | 约束 | 来源 | 对本设计的影响 |
| :-- | :--- | :--- | :--- |
| S1 | **判定谓词必须经 `getEvalPrefs()` 读取**，不得直接读 `state` | v5.3 §2「透了才生效」 | §4 步骤 ② 的门槛一律取自 `getEvalPrefs()`；站点级阈值覆盖必须能透到分区判定，否则静默无效 |
| S2 | 图片阈值字段是 `imgLumCutoff` / `imgAreaThreshold` / `imgTolerance`（180 / 48 / 35）；视频是 `whiteThreshold` / `lumThreshold`（60 / 210） | v5.3 §2 踩过的坑 | 只复用**图片那组**；写阈值相关代码前先确认字段属于哪条路径 |
| S3 | `loadState` 的枚举/默认值规范化必须**内联字面量**，不得引用 `const` 表 | v5.0 §8.4（TDZ 陷阱） | `REGION_DEFAULTS` 是 `const` 且定义在像素管线段；`loadState` 侧内联默认值，三处一致性由单测断言把关 |

另：v5.4 §2「两条采样路径必须共用同一判定函数」= §4 步骤 ② 的「复用 `evaluateImagePixelStats`
的特征口径，不新建阈值定义」这条约束的规范依据。

## 3. 掩码契约 `RegionMask`（**冻结**）

```js
{
  v: 1,                    // 契约版本；下游必须校验
  key: string,             // 缓存键：`${host}|${selectorStem}|${nw}x${nh}`
  gw: number, gh: number,  // 网格尺寸（等于采样尺寸 N）

  // —— 权威数据 ——
  data: Uint8Array,        // 长度 gw*gh；1 = 该格反色，0 = 该格保持原色
  coverage: number,        // data 中 1 的占比，0~1

  // —— 语义标注（诊断与默认方向）——
  polarity: 'carve-color' | 'carve-light',
  //   carve-color：整图偏浅 → 抠掉大面积彩色/深色块，其余反色（主场景）
  //   carve-light：整图偏深 → 抠出大面积浅色块去反色

  // —— 来源与降级 ——
  source: 'region' | 'whole' | 'none' | 'degraded',
  //   region   = 走完分割，data 有效
  //   whole    = 双门退化为整图反色（data 全 1、coverage 1）
  //   none     = 判定不反色（data 全 0、coverage 0）
  //   degraded = 读不到像素等失败，**退化为整图判定**且必须带 reason
  degrade: null | { reason: 'taint' | 'decode' | 'cross-origin' | 'no-pixels' | 'budget' },

  // —— 渲染就绪表达（下游二选一，二者必须渲染等价）——
  expr:
    | { kind: 'holes',  holes: [{ x, y, w, h }] }   // 归一化 0~1；从整图挖洞
    | { kind: 'islands', polys: [{ x, y, w, h }] }  // 归一化 0~1；孤岛式反色
    | { kind: 'bitmap', bytes: Uint8Array }          // gw*gh 灰度
}
```

### 3.1 契约不变量（单测必须全部覆盖）

| # | 不变量 |
| :-- | :--- |
| I1 | `data.length === gw * gh` |
| I2 | `source === 'whole'` ⟹ `data` 全 1 且 `coverage === 1` |
| I3 | `source === 'none'` ⟹ `data` 全 0 且 `coverage === 0` |
| I4 | `source === 'degraded'` ⟹ `degrade !== null` |
| I5 | `source === 'region'` ⟹ `degrade === null` 且 `coverage ∈ (0, 1)` 开区间 |
| I6 | `coverage` 与 `data` 的 1 计数**算术一致**（非独立计算） |
| I7 | `expr` 的三种 kind 在**同一 `data`** 上渲染结果像素级等价（v6-2 侧断言） |
| I8 | `expr.kind === 'bitmap'` ⟺ `data` 无法用 ≤ K 个矩形精确表达 |

**`data` 是唯一权威**；`expr` 是可重算的派生表达。下游若需要，可从 `data` 重建 `expr`，
但**不得**反过来从 `expr` 反推 `data`。

## 4. 分区判定管线

```
① 采样：`sampleDrawable(drawable, N)`  → N×N RGBA
   （N 默认 16；仅当区域模式开启时用 N，关闭时整条路径不执行）
② 逐格谓词：把 N×N 采样切成 **N×N 格**（每格恰好一个降采样像素 —— 由于 `drawImage` 的
   降采样是**区域平均**，每格代表源图的一小块而不是单点采样，因此逐格判定有意义），
   逐格跑**同一个单像素谓词** `classifyLightPixel(r,g,b,a,ctx)`
③ 二值化：谓词返回三态 —— `-1` 透明（完全不参与，不进分母）/ `0` 计入不透明但非浅色
   （含被原色屏蔽的）/ `1` 浅色；`cells[i] = (cls === 1) ? 1 : 0`
④ 默认方向（父 PRD R3，不得搞反）：
     invert = 全图 ∖ (面积达标的「非 lightLike」连通域)      // carve-color
   —— 即「默认该反，只有明确的彩色/深色大块被抠掉」
⑤ 形态学：闭运算（填小洞）→ 开运算（去孤立块）
⑥ 连通域 + 最小面积门：面积 < 3% 的连通域跟随邻域多数
⑦ 双门复核（§5）
⑧ 表达选择（§6）
```

### 3.1 实现修正（阶段 1 落地时发现，已生效）

原 §4 写的是「逐格算 `lightRatio_cell` 与 `avgSat_cell` 两个特征」。**实际实现不这样做**，
原因是：

`evaluateImagePixelStats` 末尾有**聚合级**守卫 `if (opaqueCount < 8) return {isLight:false}`，
单像素输入必然命中，逐格直接复用它会全部返回 false。而规范 v5.4 §2 要求
「两条采样路径必须共用同一判定函数」，另写一份谓词必然漂移。

**故把单像素谓词抽出来共用**：`buildLightTestCtx(prefs)` 预算色卡/容差/屏蔽色，
`classifyLightPixel(r,g,b,a,ctx)` 做三态判定；整图判定与逐格判定都调它。
「每格两个特征」因此塌缩为「每格一次谓词调用」—— 这是自然的，因为一格就是一个像素。

完整推理与三选一的取舍见 `implement.md` 偏离 4。


### 4.1 关键实现约束

- **② 不得引入新的阈值常量**：门槛值取自现有 `state` 的对应偏好（图片路径的
  `imgLumCutoff` 一族）。新增的只有「网格粒度 N」与「面积门」两个参数。
- **④ 的方向是本设计的核心**：直接找「该反色的格」会把白底黑字之间的白缝误判成独立
  区块，产生碎裂掩码。反过来找「大面积的非浅色块」再取补，鲁棒得多。
- **形态学在 `gw × gh` 的小网格上做**（16×16 = 256 格，3×3 邻域），成本可忽略。
  不做亚像素、不做边缘提取、不做 marching squares。
- **⑤⑥ 的顺序不可颠倒**：先形态学去噪再算连通域，否则噪点会被当成连通域参与面积门。

## 5. 双性能门

```
门 1（进分割前）：
  ratio = 整图 lightLike 占比
  ratio >= 0.97 || ratio <= 0.03  →  source='whole' | 'none'，**不做分割**
门 2（分割后）：
  coverage >= 0.97 || coverage <= 0.03 → 退回 source='whole' | 'none'，**不产出 expr**
```

> **阈值以下的 0.90/0.10 已作废（2026-09-25）**：落地时实测发现门 1 才是主场景的卡点
> （浅色占比 0.902 的图在门 1 就被短路成整图反色，嵌入的彩色内容被一起反色），
> 且两门本就同源。现取 `1 - minAreaRatio` / `minAreaRatio` = **0.97 / 0.03**，
> 由 `REGION_MIN_AREA_RATIO` 硬派生。完整理由与实测见 `implement.md` 偏离 7。

**整图 ratio 的取得**：区域模式开启时，整图统计**从 N×N 网格聚合**得到（对全部格子求并
的纯算术，不额外降采样）；区域模式关闭时，仍走现有 8×8 路径。

> **已知取舍**：N×N 聚合出的整图统计与 8×8 采样的像素基数不同，边缘图的判定可能与
> v5.0.0 **有微小差异**。这只在用户**显式开启区域模式**后发生，且此时整图结论会被
> 门 1 直接复用。默认关闭时零差异 —— 这是 AC-6 的兑付方式。

## 6. 表达选择（`expr`）

| 条件 | `expr.kind` | 用途 |
| :--- | :--- | :--- |
| 「保持原色」的连通域可精确表示为 **≤ K 个归一化矩形**（K 默认 3） | `holes` | 主场景：白底幻灯片里嵌一块矩形彩色图 → 一个洞。走矢量 `clip-path: url(#clip)`，**省一次图像解码** |
| 「反色」的连通域可精确表示为 **≤ K 个矩形** | `islands` | 对偶场景：深底图里一块矩形高亮 |
| 其余 | `bitmap` | 不规则形状。`mask-image` + 位图 |

- **矢量路径必须与位图路径渲染等价**（契约不变量 I7）。
- 「矩形化可行性」判定：把目标连通域与其外接矩形的面积做比对，差值低于容差即认为等价。
  容差参数化（默认 2% 面积偏差）。
- 位图字节：`gw*gh` 的灰度，0 = 不反色、255 = 反色，经 PNG/位图编码后供 `mask-image`。

## 7. 视频与 GIF（D5）

- **不在本片实现调度**（渲染与调度属 v6-2），但本片必须提供**可被调度的纯函数**：
  `buildRegionMask(sampledGrid, opts) → RegionMask`，无副作用、可重复调用。
- 视频的采样尺寸由 v6-2 的重算调度决定（首帧 / 场景跃变 / 心跳）；本片保证**同一输入
  得到同一输出**（纯函数），使 v6-2 的帧间沿用是安全的。
- GIF 走 `<img>` 路径，采样的是**当前帧**。

## 8. 缓存

- 键：`${host}|${selectorStem}|${naturalWidth}x${naturalHeight}`。
  - 用 `naturalWidth/Height`（固有尺寸）而非 `clientWidth/Height`，避免布局变化导致抖动；
    归一化掩码本身与渲染尺寸无关（`objectBoundingBox`）。
- 结构：`Map` + LRU，上限默认 **200**（对齐 `ImageFxEngine.lruMax` 的既有先例）。
- 淘汰时**不持有**大对象：`data`（256 B）与 `expr.bitmap`（256 B）都很小；若走位图路径
  生成了编码后的 blob URL，需一并 revoke（参照 `ImageFxEngine.pendingRevoke` 的既有做法）。
- **AC 要求**：同图重复出现不产生第二次分割。

## 9. 与 Action Registry 的接缝

- **不改 `SOURCES` 表的形状**（那是 v5-1 冻结的契约）。区域结论作为**像素路径内部**的一支：
  - `source` 仍为 `'pixel'`；
  - `reason` 新增 `'region'`；
  - 落库与写点仍经 `arbitrate` / `applyInvertState`，**不另建优先级链**。
- `reason: 'region'` 进入撤销栈时按**自动来源**处理（`isAutoReason` 已按白名单反判，
  `'region'` 不在 `NON_AUTO_REASONS` 里，天然满足 —— 单测确认）。
- 本片只在像素判定处加一个**可关闭的提前分支**：区域模式关闭时该分支不进入，
  行为与 v5.0.0 逐字节一致。

## 10. 降级与失败放行

| 情况 | 行为 |
| :--- | :--- |
| `sampleDrawable` 抛错（tainted canvas） | `source='degraded'`，`degrade.reason='taint'`，**退化整图判定** |
| blob 解码链失败 | `degrade.reason='decode'` |
| 跨域且无回退 | `degrade.reason='cross-origin'` |
| 采样到全透明（`opaqueCount` 过低） | `degrade.reason='no-pixels'` |
| 命中预算门 | `degrade.reason='budget'` |

**统一纪律**：任何降级都**退化为整图判定**（现有行为），**绝不**产出「拿不到像素就全遮住」
或「拿不到像素就乱挂掩码」的结果。降级**必须可观测**（`StatsManager` 按 reason 分别计数）。

## 11. 权衡与替代方案

| 方案 | 取舍 |
| :--- | :--- |
| **本设计：N×N 粗网格 + 形态学 + 位图/矢量双表达** | 复用现有特征，零新依赖，成本可控。代价：区域边界受网格粒度限制（16×16 下每格约 6% 宽度），细碎形状表达不了 |
| 像素级连通域（对全分辨率做 flood fill） | 边界精确，但需全分辨率像素缓冲 + 遍历，成本远超预算，且跨域仍失效 |
| 语义分割 / ML | 直接违反零依赖与非目标 |
| marching squares 提轮廓 | 边界更精细，但实现量大；且 D3 已选「保守大块」，粒度本来就不需要轮廓精度。**列为后续可选优化** |

## 12. 兼容性与回滚

- **默认关闭**：`regionSegment` 偏好默认 `false`。
- **关闭时零影响**：不新增属性写入、不新增采样调用、不新增 CSS 规则。
- **回滚点**：本片只新增函数与一个可关闭分支；回滚 = 关开关或 revert 提交，无数据迁移。
- 若 v6-3 的自校准写入参数，需支持**一键回滚到默认参数**（v6-3 负责，本片只提供
  参数默认值的单一真源）。

## 13. 未决项（交给实现阶段定，不阻塞契约冻结）—— **已全部回填实测结论**

1. `N` 的默认值取 16 还是 24 —— 需实测单图耗时后再定，**上限 32**。
   **已决（阶段 3 bench）**：**取 16**。实测单图掩码构建（25 轮均值）：N=16 典型 0.040ms /
   随机 0.020ms；N=32 典型 0.045ms —— 两者**同量级**，耗时不是选型的约束条件。
   故 16 与 24/32 的取舍交给**边界精度 vs 位图体积/矢量命中率**决定，默认取更省的一侧；
   若 v6-2 的渲染实测显示 16 的边界过粗，可直接上调到 24/32 而无需重新做性能权衡。
2. `K`（矢量矩形化上限）默认 3 —— 需实测主场景命中率后再定。
   **已决（阶段 4）**：**保持 3**。实测：主场景（一个矩形嵌入块）**1 个矩形**即命中矢量快路径；
   两个相距较远的 3×3 块需要 **2 个**；K=1 时同一掩码退位图（单测断言）。
   K=3 覆盖「主场景 + 两块散布」，且不会让矢量表达的矩形数多到失去"省一次解码"的意义。
3. ~~逐格谓词的具体门槛：直接复用整图门槛，还是给逐格更宽松的门槛~~
   **已决（阶段 1）**：**直接复用整图门槛，不做更宽松的逐格门槛**。两个理由：
   (a) 逐格输入不是单点采样而是 `drawImage` 的区域平均，噪声预期低于原估计；
   (b) 放宽门槛会破坏「逐格与整图同源」这条**可断言**的性质（单测已断言
   `regionGridRatio === evaluateImagePixelStats().lightRatio`）。去噪交给阶段 2 的形态学。
4. 形态学核：3×3 固定，还是按 `gw` 比例缩放。
   **已决（阶段 2）**：**固定 3×3（8 邻域，腐蚀走边界复制）**。三个理由：
   (a) 厚度门要靠 3×3 才成立（1~2 格厚的细笔划要被抹除，见偏离 5）；
   (b) 网格只有 8×8~32×32，按 `gw` 比例缩放会让小网格上的核退化成 1×1 —— 噪声重新变成"特征"；
   (c) 固定核让「最小可抠特征块 = 3×3 格 = 约 3% 图面积」成为**可解释、可断言**的常量
   （这正是双门阈值取 0.97/0.03 的来源，见偏离 7）。

   （可能互相抵消），互不相交就没有二义性。I8 的「≤K 个矩形精确表达」据此定义为
