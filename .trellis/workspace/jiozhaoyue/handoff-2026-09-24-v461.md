## 三、本次唯一的行为改动（v4.6.1）

### 改了什么

`universal-smart-invert.user.js` 的 `whenBodyReady()`：`setInterval(…, 50)` 轮询
→ `MutationObserver` 事件驱动（保留轮询与硬超时作兜底）。

### 为什么

扩展形态 `run_at: document_start` 时 `document.body` 尚未创建，原实现的 50ms 轮询
使 boot 回调平均晚 **50ms** 才起跑（三次复现 50/52/53ms），而**全部引擎构造本身仅约 10ms** ——
即这是扩展启动路径上最大的单项可归因延迟。

### 踩过的坑（重要，勿重蹈）

**必须 `observe(document)`，不能 `observe(document.documentElement)`**：
`document_start` 时刻 `document.documentElement` **仍是 `null`**（实测 `readyState=loading`）。
`observe(null)` 抛 `parameter 1 is not of type 'Node'`，被 try/catch 吞掉后
**静默退化回 50ms 轮询** —— 第一次修复就是这样失效的，由 `dev/probe-diag-bodyready.js` 证实。

### A/B 实测证据（各 3 次复现，探针 `dev/probe-boot-breakdown.js`）

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 等待 body 出现 | 51 / 52 / 51 ms | **2 / 1 / 2 ms** |
| 首个图片决策 | 75 / 77 / 77 ms | **44 / 46 / 49 ms**（约 −40%） |

### 为何版本 bump 到 4.6.1

这是真实的行为/性能改动，按项目惯例 bump patch。已同步：`@version`、`SCRIPT_VERSION`、
`test.js` 断言、README 双语徽章、`extension/manifest.json`（重建产出）。

## 四、审计结论（用户两个问题的答案）

### Q1：插件是否已完全本地化？

**是。判定与网络彻底解耦。**

- 运行时代码**不读取任何网络状态量**：`navigator.onLine`、`connection.effectiveType`、
  `downlink` 全部未发现；也不监听 `online`/`offline` 事件（代码级核查）。
- **网络通道仅两类**：
  1. 规则包链接导入（`gmFetchText`）—— **纯手动**，仅用户点击按钮时执行；
  2. 跨域像素采样的 blob 回退（`gmFetchBlob`）—— 同源图直接读像素**不联网**；
     仅当浏览器因跨域污染禁止读像素时，才取该图**自身数据**一次；失败即标记未决并保留原样。
- 无遥测、无更新检查、无统计上报；规则/站点预设/种子全内置，启动时不向任何远程地址拉取。

> ⚠️ README 初稿曾把通道 ② 写成「仅在手动动作或同源缓存内触发」，**不准确，已更正**。
> 接手者若继续动 README 这一段，请保留更正后的措辞。

### Q2：能否抢先识别？

**能，且已量化。**

- 机制：三档本地证据（A 像素已解码 / B 有布局盒未解码 → 立即本地保守判定 / C 无布局 → 登记待判）
  + 规则结论先于字节落地 + `load`/IO/Mutation 唤醒升级。
- 实测（`dev/probe-weaknet.js`，限速 300kbps / 400ms RTT）：首屏 6/6 图全部落判。
  - 正常网：**152ms**
  - 弱网：**569ms**
  - 差值 417ms ≈ 探针注入的 400ms RTT
  - → **插件可归因延迟恒定约 65~77ms**；其余全是取回 HTML 文档本身的网络耗时
    （插件在拿到 DOM 之前根本无法运行）。

### Q3（父 PRD 遗留裁决点）：弱网 500ms AC 未达标的 560/569ms 怎么办？

**审计给出的新信息：60ms 缺口的大部分不是插件开销**，而是注入的 RTT + 导航开销。
插件自身那 65~77ms 中，本次已把 ~50ms 的轮询等待修掉。

## 六、方法论教训（已写入 spec，此处摘要）

1. **轮询打点在本项目不可信** —— boot 同步块占满主线程时 `setInterval` 被推迟，
   曾得到「所有引擎同一时刻、且晚于首个决策」的非物理结果。主线程繁忙期只能用事件驱动打点。
2. **插桩要精确锚点，不要宽正则** —— 宽正则 `= new X(...)` 全局替换误匹配 66 处并破坏脚本；
   改用 9 行唯一赋值语句做锚点，零风险。
3. **改测试前先用对照实验定性** —— 复制 `test.js` 仅改等待时长，区分「产品缺陷」与
   「测试等待不足」。本次两处断言（30ms / 60ms）均为后者。
4. **Git Bash heredoc 会吞反斜杠** —— Windows 路径写脚本一律用 Write 工具，不要用 heredoc。
   （另：`/tmp` 在 Git Bash 与 Node 之间路径不通，临时文件要写在仓库内。）
